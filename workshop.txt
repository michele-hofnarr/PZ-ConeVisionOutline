title=Cone Vision Outline
description=Works only when the "Melee outline" option is enabled (Options > Display).
description=
description=White outline for zombies and animals in vision cone when aiming (RMB); green outline for melee hit-list targets. Firearm: no outline. Respects ShortSighted trait.
description=
description=Uses the game's built-in vision system. Works on foot and in vehicles, day and night. Hit-list logic from Aim Outline by Kreb (Workshop ID: 3404684285). Single player only.
description=
description=v0.7 - Added an indicator for zombies that are above the player. Now zombies right at the top of the stairs won't be a surprise.
description=
description=v0.8 - Overlay for floor above (stairs) is always on. Mod options: cone outline color and intensity (slider 0–1). Melee hit-list outline unchanged.
description=
description=v0.9 - Added 2 new options to the mod settings:
description=
description=1. Scale outline by light level
description=   When on, outline alpha is multiplied by the tile light level (darker = fainter outline, full dark = no outline).
description=2. Vehicle: outlines always on
description=   When on, in a vehicle outlines are shown without holding RMB (aim/look). When off, same as vanilla: hold RMB to see outlines.
description=
description=v1.0 - Updated for game build 42.20.0. Tested in singleplayer; multiplayer is untested, I do not know whether it works there.
description=
description=The mod had stopped working completely on current builds:
description=
description=1. IsoCell.getObjectList() now returns a Set, which has no indexed access, so the outline loop threw an error every frame. Lua must use getObjectListForLua() instead.
description=2. Mod option labels showed raw translation keys - build 42 moved translations from .txt files to .json.
description=
description=Lua errors are no longer swallowed silently; they are reported to console.txt so future engine changes are visible.
description=
description=v1.1 - The green melee outline now works without -debug.
description=
description=Until now the hit-list outline read the game's hit list through Lua reflection (getClassField and friends). Build 42.15 locked those functions behind debug mode, so on a normal launch that code threw an exception every frame and the green outline never appeared. This is what the 42.16 bug reports were about, and why people found that the mod "only works in debug mode".
description=
description=The reflection is gone. The mod now picks up melee hit-list targets from the engine's own highlight pass, so no debug mode and no third-party reflection patch is needed. The hit list is the real one the game calculates, not an approximation.
description=
description=Tested in singleplayer on 42.20.0. Multiplayer is still untested.
description=
description=v1.2 - New option: "Outline animals", on by default.
description=
description=Turn it off if you only want zombies outlined. It covers everything the mod draws for animals - the cone outline, the green melee outline and the floor-above indicator. One caveat: with a melee weapon in hand the game itself still highlights animals it counts as valid targets, and that highlight is not the mod's to switch off.
description=
description=v1.3 - New default visibility check, a fix to "Scale outline by light level", and two new options: "Scale outline by fog" and "Outlines always on" (both off by default).
description=
description=The mod now asks the engine directly which zombies and animals it has already decided to draw, the same signal build 42's own vision system uses, instead of reconstructing that decision from square visibility and the mod's own vision-cone math. Found by reading a different outline mod, RadVision (Workshop ID: 3774647043). The old approach is still available as "Legacy outline mode" if you ever prefer it.
description=
description="Scale outline by light level" reads the tile's light level correctly on this build now. "Scale outline by fog" is new: the game only tracks one fog thickness for the whole world, not per tile, so this approximates it by fading outlines toward the edge of your current clear-visibility radius.
description=
description="Outlines always on" is also new: turn it on and outlines show all the time, whether you are aiming (RMB) or not, on foot or in a vehicle. The existing "Vehicle: outlines always on" option still works on its own if you only want that narrower behavior.
description=
description=Known issue: with either of these two dimming options on, the outline can occasionally render behind certain thin scene objects (support posts, roof beams) instead of through them, for a few seconds at a time, seemingly tied to camera or character position. I could not pin down the cause after extensive testing - it does not depend on which game function supplies the light/fog value, nor on how many distinct brightness levels are in play at once. This looks like a limitation in the game's own outline renderer, not something fixable from the mod's side. With both options off, outlines go back to being static (full brightness whenever the game renders the zombie at all) and this issue does not occur.
description=
description=Tested in singleplayer on 42.20.0. Multiplayer is still untested.
description=
